Two fixes: one to the annotation editor's finish buttons, one to the error an
SFTP destination shows when it is given the wrong kind of key.

## The editor's finish buttons are readable again

After a capture, the editor's toolbar ends in four buttons — **Cancel**, **Copy**,
**Save**, and **Upload** — that decide what happens to the annotated image. They
had no icons and were packed into the same row as every drawing tool, so at the
editor's window size their labels were squeezed down to about one letter each and
read as a meaningless "C  C  …  U". There was no obvious way to say you were done.

The four buttons now carry icons alongside full labels, **Save** and **Upload**
are shown as prominent (blue) buttons, and the editor opens wide enough — and no
longer shrinks below the width the toolbar needs — that the labels can never be
truncated again. What each does is unchanged: **Save** writes to disk (and
history), **Upload** saves and uploads, **Copy** puts the image on the clipboard,
and **Cancel** discards the capture.

## A clearer error for an RSA SFTP key

An SFTP destination configured with an **RSA** private key used to fail with an
opaque authentication error. It now names the cause — the SSH library can only
sign with the legacy `ssh-rsa` (SHA-1) algorithm that OpenSSH 8.8 and newer reject
by default — and points you at using an Ed25519 key instead.
