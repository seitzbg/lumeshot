Lumeshot now updates itself, and a code review of the whole app turned up twelve
defects — several of which could lose a capture, an upload, or a credential.

Eleven of them are listed below. The twelfth stopped the app launching at all and
never reached a published build, so no released version was affected by it.

## Automatic updates

Lumeshot checks for updates daily and on demand, then downloads, verifies and
installs them in place. Downloading a dmg and dragging it to Applications is no
longer part of updating.

This release is the one you install by hand; from here on it updates itself.

## Fixes that protect your data

- **Uploads no longer overwrite each other.** With **Save a copy** switched off,
  every capture was uploaded under the same name, so destinations addressed by
  filename — S3, SFTP and FTP — replaced the previous capture each time, and with
  no local copy there was nothing to recover. Each upload now gets its own name.
- **A failed uploader edit no longer destroys working credentials.** If saving an
  edited uploader failed part way, it could leave the destination with no
  credentials at all, or with a rejected new key sitting beside the restored old
  password — and SFTP would then use the rejected key.
- **Editing an SFTP uploader keeps its pinned host key.** Renaming a destination
  could silently discard the fingerprint learned on the first connection, after
  which Lumeshot trusted whatever the server presented next. A pin is now kept
  unless you point the destination at a different host or port.
- **Re-uploading a capture cannot delete the earlier upload.** A failed second
  upload inherited the first one's remote deletion link, so deleting the failure
  deleted the copy that had worked.

## Fixes that protect what you meant to hide

- **A crop that cannot be applied stops the export.** Drawing a crop outside the
  image — easy to do in the grey margins around it — used to export the whole,
  uncropped screenshot instead. Crops are now confined to the image, and an
  export that still cannot apply one shows an error rather than sending the
  original.
- **A redaction that fails to render stops the export.** If blur or pixelate
  could not be drawn, the image was delivered without them. Copy, Save and
  Upload now refuse, and the editor stays open so nothing is lost.
- **Upload failures no longer log the server's reply.** A server that echoes your
  request back in an error could write an API key or a deletion token into
  `~/Library/Logs/Lumeshot.log`. The reason for the failure is still recorded.

## Other fixes

- **A failed upload is reported as a failure.** A custom uploader whose response
  was missing the value its URL template asked for could report success and copy
  a broken link to the clipboard.
- **FTP directories starting with `/` are absolute.** They were being treated as
  relative to the login directory, so uploads landed somewhere other than the
  configured path while the copied link claimed otherwise. If you worked around
  this by writing the path relative to your login directory, drop the leading
  slash to keep the old behaviour. Servers that lock the login to `/` are
  unaffected.
- **The menu bar no longer claims to be recording after a failed start.** It
  could show a running timer with no recording behind it, which stopping would
  not clear.
- **Settings changes no longer overwrite each other.** A background change, such
  as learning an SSH host key mid-upload, could discard a preference saved at the
  same moment.

## Upgrading

Download the dmg and replace your existing copy. Your settings, history and
stored credentials are kept.
